# 2026-09-30 触摸响应与边缘返回

## 修改

- SSD1677 BUSY 清除后的输入稳定窗口由 500 ms 改为 32 ms，减少每次刷新
  468 ms 的额外等待。面板波形、BUSY 等待和每 10 次局刷的维护全刷保持原有策略。
- UI 主线程进入交互界面时由优先级 0 调至 10，FT6336 保持优先级 8。
  触摸采样可以抢占 LVGL 布局；编译断言禁止将 UI 优先级配置得高于触摸线程。
- 左侧最靠边 48 px 内向右位移 32 px 即识别 BACK，允许纵向位移不超过横向
  两倍的斜向右滑；其余左侧四分之一区域保留 60 px、横向主导的返回阈值。
  纯纵向滑动和屏幕中部翻页保持原语义。
- BACK/HOME 达到阈值时即入队，同次按压已消费的边缘动作在释放时不再重复。
  阅读、菜单、目录和确认页继续使用原有层级返回规则。
- 刷新期间保留一个动作，BACK 可替换普通点击，HOME 可替换 BACK；后续普通
  点击不能覆盖导航动作。实体键也进入这条暂存路径。
- 普通点击的防抖窗口由 120 ms 缩至 40 ms，边缘导航不受此窗口限制。
- 事件携带捕获时间，日志分别显示排队等待和动作总耗时。
- 工作区新增的 24 px 中文字体超过 LVGL 默认字形索引容量，启用
  `LV_FONT_FMT_TXT_LARGE`，避免索引截断及构建错误。

## 构建与软件验证

字体/UI 资源同时在工作区生成，为固定验证对象，本轮最终镜像使用一次源码
快照构建。下面结果属于该镜像，不代表随后工作区中所有改动均已刷入。

- 快照主机测试 23 组通过，含原有测试及新增的 UI 布局测试；边缘距离、斜向
  返回、纯纵向保留、非法坐标和刷新期间导航优先级均有覆盖。
- 默认、partial demo、driver selftest、selftest + touch power 四配置构建通过。
- 内部 DRAM 分别为 324608、305136、307784、312056 bytes，占用
  81.33%、76.45%、77.12%、78.19%，均低于 85% 门槛。
- power 组合确认 `PAPERMONO_POWER_HIL_DEEP_SLEEP_TOUCH=y` 和 `POWEROFF=y`；
  此轮只构建该组合，没有刷入或执行电源耐久测试。
- 最终默认镜像位于 `build-response/zephyr/zephyr.bin`，4320292 bytes，SHA-256：
  `91e53ae80a2d5170045e22899c2de09904255a469ff6d16161e5667a67930b8c`。
  通过 ESP32-S3 原生 USB 写入，esptool 报告 `Hash of data verified`。

## 实机证据

先刷入缩短稳定窗口的中间镜像，真实触摸捕获到：

- 空闲时 `UI processing touch ... wait=0 ms`，页面切换总耗时 985–1112 ms；
  其中 SSD1677 局刷为 737–739 ms，结束后 32–33 ms 完成 UI 动作。
- 刷新期间的动作被保留，在局刷完成后的 32 ms 稳定窗口结束时交给应用，
  本次等待 316 ms，没有再增加原有的 500 ms。
- UI 布局抢占触摸回调约 300 ms，随后最终版本调整线程优先级。
- 一次边缘操作为 `(5,498) -> (52,580)`，原判定为 DOWN；最终版本将这条
  斜向轨迹纳入 BACK，并补充主机回归用例。

最终镜像退出调试器后 USB 应用复位，完成 4313 ms 全刷、LVGL 渲染、737 ms
局刷，Wi-Fi 和 BLE 服务初始化通过。最终边缘手势与实际手感仍以物理交互
日志/用户反馈为验收依据。

TF 初始化仍出现 `Card never left busy state`（-134），内容应用读写仍有独立
问题。维护全刷仍约 4.3 秒，墨水屏物理刷新不能用触摸入队耗时替代。

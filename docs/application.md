# PaperMono 个人信息终端应用说明

## 运行模型

默认固件以 `papermono_app_descriptor` 描述应用，路由器统一处理打开、返回、
渲染和生命周期。输入回调只把实体键和触摸手势写入消息队列，网络、BLE 和
存储后台线程也只投递状态变化；所有 LVGL 操作都在 UI 线程执行。

`papermono_display_scheduler` 接收 `AUTO`、`FAST` 和 `FULL` 三种刷新请求，
负责刷新锁、刷新期间输入暂存、32 ms 稳定窗口、局刷计数、维护全刷和失败
恢复。应用不能直接驱动物理刷新。

## 页面

## 通用操作

- 首页左右实体键进入“全部应用”；触摸首页卡片打开对应快捷入口。
- 应用列表轻触直角九宫格入口打开；左右实体键或上下滑动切换两页，从左边缘
  开始右滑返回。第二页未使用的七个格子保持空白且不会触发应用。
- 有分页的列表使用左右实体键，部分页面也支持上下滑动。
- 从屏幕左侧四分之一内开始向右滑是全局返回；从底部 14% 区域开始向上滑
  直接回首页。阅读器会先按“目录/书签 → 菜单 → 阅读 → 书库”的层级返回。
- 左侧最靠边的 48 px 内向右滑动 32 px 即可返回，其余左侧四分之一区域为
  60 px。最靠边区域允许斜向右滑（纵向位移不超过横向的两倍）；纯上下滑动仍
  留给应用。边缘导航在达到距离时立即提交，每次按压只执行一次，松手不会重复返回。
- 返回手势在应用列表、内容中心、遥控器、硬件工具、系统、电源和设置页使用相同
  路由语义；确认页收到返回或回首页时会取消当前确认，不会把确认状态遗留到下次
  进入电源页。轻触取消、返回页脚或右滑返回时，连接/恢复确认回到设置，
  休眠/关机确认回到电源选项。
- 墨水屏刷新期间仍持续采样 FT6336；首个完整触摸手势会被暂存，刷新完成并
  经过稳定窗口后再交给当前页面。返回和回首页优先于暂存的普通点击；实体键也
  暂存一个动作，避免刷新时丢按键；网络、BLE、
  NTP 和内容变更等系统事件会合并保留并在刷新后重新入队。

实体键、触摸和系统事件在入队时带明确的来源标记。启动器、遥控器、设置页、
电源确认页和阅读菜单的关键操作复用可见控件的矩形布局；启动器的 3×3 图标
格子按行优先映射，其他列表继续使用带显式间距的网格命中。实体键路径与触摸
路径仍汇入同一组应用动作。

除左侧边缘返回区外，触摸释放时的短距离位移采用连续阈值：59 px 以内仍是轻触，60 px 起才可分类
为滑动，避免 31–59 px 的输入死区。轻触和长按使用首次接触点命中控件，不会因
抬手时手指滚动而漂移到相邻卡片；滑动也使用首次接触点作为区域锚点，方向仍由
起止位移判断。最短有效按压为 5 ms，覆盖 FT6336 在 8 ms 轮询周期内捕获的一帧
短触摸。

交互 UI 主线程使用优先级 10，触摸线程使用优先级 8（数值越小越优先），让
触摸采样可以抢占 LVGL 页面布局。USB 日志记录事件等待时间与动作总耗时，区分
采样/排队延迟和墨水屏物理刷新时间。

内容面在创建后先完成一次 LVGL 布局，再按实际宽高布置标题、正文和状态行，避免
读取尚未解析的零尺寸导致正文被裁掉。16 px 内置 CJK 字体也覆盖 ASCII，并用于
顶部连接状态和卡片小字；其 1-bit 笔画直接适配单色帧缓冲，不使用小字号抗锯齿
字体做阈值转换。

## Field Notes 界面系统

设备界面按 [首版设计参考](design-references/papermono-field-notes-v1.png) 和
[扩展参考](design-references/field-notes-expanded/) / [剩余页面参考](design-references/field-notes-remaining/) 实现：
纯黑白、纸白为主、衬线大时钟、横线分区和直角图标网格。首页和启动器底部
使用相同的首页/应用/设置导航。系统状态、电源仍可从应用入口进入。

首页显示真实电池电压、连接状态、最近阅读、下一日程和最多两个未完成待办。
RTC 无效时显示校时提示；跨日事件显示日期。轻触“继续阅读”恢复最近书籍，
无有效记录时打开书库；缺少已加载进度时显示“已有记录”，不编造百分比。

启动器起点 `(22,124)`，单格 `136×180`，列间距 14、行间距 16；第一页九个
应用，第二页设置和电源。间隙和空白位置不可点击。图标使用原创建模的二值
透明度 A8 资源，最终屏幕仍为 1-bit，避免索引图像解码兼容问题。

阅读页使用 24 px 衬线字库和三档密度；分页、行距和页边距共用参数，同时为
标点禁则预留两个字格。页面仅显示当前页和近似进度，不虚构整本书页数。
书库、微信读书、日历、待办、便签、信息卡片、内容中心、遥控器、工具、系统、
设置、电源以及阅读菜单/目录/书签和各确认页都已应用扩展的 Field Notes 布局。

详情页采用 22 px 边距、48 px 衬线页头、24 px 主文与 16 px 元数据；
标题分隔线在 `y=116`，通用列表从 `y=148` 开始，返回页脚从 `y=724` 开始。
五行列表的行高/间距为 `104/8`，七行阅读菜单为 `76/4`；微信读书书架在计数
和同步时间下方使用自己的五行布局。设置行、工具首项和确认按钮的可见区域与
命中范围共享 `include/papermono/ui_layout.h`，间隙不会触发操作。

阅读菜单、书签、微信读书书架、便签和信息行使用 48 px 内容/动作图标通道；
电源和确认用 96 px 对应动作符号。缺少内容的页面使用 176 px 焦点图标与
40 px 状态标题，并保留恢复说明；微信读书的“打开内容中心”按钮在 `y=490`，
其导入操作、说明及只读摘要区彼此分开。详情列表用细横线而非完整卡片框，
实际按钮保持黑字白底，确认与取消分别用 2 px 和 1 px 描边。

Wi-Fi 的忘记网络与存储格式化等确认复用同一确认组件，保持 48 px 居中标题、
96 px 动作图标及原有确认/取消位置；标题字库包含新增的存储和网络文字。
Wi-Fi 扫描空结果沿用 176 px 焦点图标与 40 px 状态标题，同时保留上方网络操作。
密码键盘的字母、符号和底排功能键使用 24 px 衬线字，窄键中的“空格”保留
16 px，以容纳完整双字；键盘命中和凭据处理没有随排版调整改变。
当前 32 个主机状态的复核记录见
[2026-10-21 一致性复核](design-references/field-notes-review-20261021/validation.md)。

遥控器发送控件只在 HID 已初始化、已连接、已安全配对、未挂起且没有可见
配对码时可用。等待连接、配对、主机恢复和未启用状态显示实际说明，仍可
切换媒体/演示/鼠标/语音模式并返回；发送或连接失败会显示错误。界面渲染、事件
分发和实际发送入口使用同一可用性条件。

启用语音输入时，模式标签由三格 140 px 改为四格 103 px、间距 8 px（仍从
`(22,212)` 开始并保持 64 px 高），新增「语音」页：436 × 250 描边语音区、
几何麦克风和 24 px「语音输入」标题，状态文字来自麦克风工作线程（启动、
传音、停止、失败、等待订阅，以及上次会话时长与字节数）。按住语音区开始、
松开停止，不显示计时器或电平表；离开页面、切换模式、返回、回首页或休眠都会
停止并关闭麦克风电源。电脑端需要运行接收器并选择虚拟麦克风，设备无法验证，
因此只作为提示出现。

详细坐标、字体和内存边界见根目录 `DESIGN.md`。42 张 480×800 I1 原生
主机截图和 overview-1 至 overview-9 位于
[实现预览](design-references/field-notes-applied/)；它们由实际 UI/LVGL 渲染，
使用合成内容与硬件 fixture，不是设备照片。
[软件验证记录](design-references/field-notes-applied/validation.md) 分别记录主机检查、
64 KiB LVGL 渲染和固件构建；这些结果不证明实机触摸、BLE 发送、显示残影、
唤醒或设备堆余量。

## 阅读器操作

- 书库列表：左右实体键选择，轻触打开，长按重新扫描 TF 卡。
- 阅读页：左/右实体键或正文左右区域翻页；长按或轻触底部“书签”切换书签；
  轻触正文中间或底部页码打开阅读菜单。顶部按钮在 EPUB 中打开目录，在 TXT
  中打开菜单；边缘右滑返回书库。
- 阅读菜单：进入目录或书签列表；轻触密度项在紧凑、标准、宽松间循环；
  TXT 长按编码项可在自动、UTF-8 和 GBK 间切换；前光项轻触或右滑增档、
  左滑减档，按 0/25/50/75/100% 五档调节，长按直接关闭。
- 翻页命令显式携带 `PAPERMONO_REFRESH_FAST` 到集中显示调度器，并由驱动记录为刷新
  意图；基线有效时走局刷，达到 `CONFIG_PAPERMONO_PARTIAL_REFRESH_LIMIT`、基线失效
  或局刷失败时自动维护全刷。启用 `CONFIG_PAPERMONO_MAINTENANCE_OPPORTUNISTIC`
  时，维护全刷会在下一次非 FAST 渲染（翻页离开、菜单、休眠）提前执行，不提高上限
  （默认关闭）。页面应用不能直接调用 SSD1677。
- 已在第一页/末页或列表边界时不提交重复刷新；损坏或被拔出的书籍会保留
  书库列表并显示错误，不会误报成空书库。
- TXT/EPUB 分页应用简体中文标点禁则：开引号、开括号不留在行尾，句号、
  逗号、闭引号和闭括号不落在行首；必要时允许结束标点使用最多两个边距字格。
- 最近阅读只在路径、大小和 FAT 修改时间生成的稳定 ID 仍匹配时显示；文件
  消失后状态保留在 NVS，但不会显示为可打开内容。
- 设备只在上次确实停留于阅读页时恢复阅读会话；主动返回书库列表后，重启或
  再次进入书库仍停留在列表。通过 Wi-Fi/BLE 导入或删除内容后，当前书库列表
  会在 UI 线程重新扫描并更新，不需要重启设备。

阅读器把页起始偏移保存到 TF 卡的
`/SD:/papermono/.cache/reader/<book-id>.pages`，因此即使翻过超过 RAM 内
的 32 页历史，仍可稳定向前翻页。索引文件有版本和校验，并与书籍稳定
ID、大小、修改时间、TXT/EPUB 类型、编码和阅读密度绑定。书籍或排版参数
变化、索引损坏或末尾写入不完整时会自动重建；TF 卡写入失败只会退回
到 RAM 历史，不阻断阅读。

## 微信读书实验书架

- 从内容中心上传固定文件名 `weread-v1.json`，类型选择“微信读书书架”；上传
  仍走 TF 临时文件、校验、原子替换和内容变更消息，不从网络线程调用 LVGL。
- 列表每页显示 5 本；左右实体键或普通左右滑动选择，上下滑动按页移动，轻触
  条目查看详情。详情页左右切换书籍；左边缘右滑或轻触底部先回列表，列表根页
  再执行同一手势才退出应用。长按重新读取 TF 文件。
- 该阶段只消费规范化元数据，不包含扫码登录、Cookie/token、章节下载、EPUB
  转换或进度回写。完整 JSON 契约和示例见 `docs/content-api.md` 与
  `docs/weread-v1.example.json`。
- 详情页仅在摘要提供进度时使用 48 px 数字百分比；缺少进度时以 24 px 主文
  显示“未提供进度”，不补写数值。

## 电源和恢复

默认空闲 10 分钟保留屏幕画面并进入 ESP32-S3 深睡，可选关闭、1、5、10 或
30 分钟。触摸中断、电源键或左右翻页键唤醒。从屏幕菜单操作的主动休眠、关机、
重新配网和清除 BLE 配对都需要二次确认。设备已启动后短按电源键则直接请求
休眠；内容上传/配网写入事务进行中暂不执行，保留当前页面和文件事务。

M5PM1 驱动在冷启动时也配置单击中断，清除硬件中断并释放 I²C 锁后，通过
Zephyr Input 报告 `INPUT_KEY_POWER`。输入回调只投递 UI 队列，真正的显示和
低功耗切换在 UI 线程完成。只接受单击，不把唤醒或双击中断转换为休眠。
启动期间捕获的电源键事件不进入队列，防止 PMIC 延迟锁存的唤醒单击导致刚醒
又睡；UI 完整启动后才接受下一次单击。刷新期间保留一个电源键请求，其优先级
高于返回/首页手势，重复请求合并。双击关机、长按及下载恢复仍遵从 PMIC 配置。

进入深睡前会关闭前光和 RGB 状态灯、停止蜂鸣器/NFC RF/麦克风并让 SSD1677 进入合适的
电源状态。唤醒后重新初始化显示并执行完整刷新以重建局刷基线，然后恢复持久化
的当前应用。USB Serial/JTAG 在深睡期间会断开，唤醒后重新枚举。

板级 FT6336 驱动按官方时序驱动 M5IOE1 的触摸供电与复位，启动后由独立 4 KiB
线程以 8 ms 周期读取完整触摸帧，不再依赖全局 system workqueue；探测失败时
后台恢复，连续 I2C 失败或控制器转离线都会在 100 ms 后释放陈旧触点。FT6336
和应用都使用 480x800 竖屏原点，raw x/y 直接映射；越界帧会被
拒绝并单独计数，不会钳位到屏幕边缘触发控件。GPIO4 即使在轮询模式也会配置为
带上拉的唤醒输入；ESP32-S3 的数字 GPIO 与 RTC IO 上拉相互独立，因此板级
`int-gpios` 和驱动都显式带 `GPIO_INT_WAKEUP`，保证切换为 EXT0 RTC 输入后仍有
确定的空闲高电平。
深睡保留 GPIO4 的 EXT0 触摸唤醒，同时为 GPIO2/3 翻页键和 GPIO1 的 M5PM1 IRQ
配置 EXT1 ANY_LOW。三根新增输入也带 RTC 上拉。休眠前清除陈旧 PMIC 中断，
显式开启按键单击/唤醒中断，并禁用单击复位，避免短按在唤醒恢复期间复位 MCU；
长按、双击关机和下载恢复配置不变。`pmic_irq` 表示 GPIO1 唤醒，不等同于
PMIC 完全关机后重新供电的 `pmic_button`；其他 PMIC 事件也可能触发 IRQ。
启动时最早读取的唤醒来源会缓存到本次运行结束，并显示在硬件工具页及公开
`/api/v1/status` 的 `power.wake_cause`；即使随后确认并清除 PMIC 中断状态，也不会
丢失诊断证据。
主动休眠在显示“设备休眠中”之前，会只读检查全部低有效唤醒输入已经释放；检查过程
不会改写运行中的触摸状态。唤醒源未就绪或底层电源动作返回时，休眠会取消，界面
显示错误并执行完整恢复刷新，同时恢复已保存的前光亮度和状态灯，UI 事件循环继续
运行，不会停留在休眠页。

## RGB 状态指示

状态灯由单一调度模块合并存储、Wi-Fi、BLE 和传输状态，业务模块不直接选择颜色，
因此并发状态不会互相覆盖。启动/服务故障会独立保留，临时 UI 故障可在完整恢复
刷新后清除，后者不会误清仍存在的启动故障。优先级从错误、警告、传输、配对、
连接到正常待机：

| 颜色 | 含义 |
| --- | --- |
| 白色 | 启动初始化 |
| 低亮绿色 | 系统就绪 |
| 蓝色 | SoftAP 配网或 Wi-Fi 连接中 |
| 青色 | Wi-Fi 或已加密 BLE 主机已连接 |
| 黄色 | HTTP 上传、配网提交或 BLE 小数据同步 |
| 紫色 | BLE 配对码等待确认 |
| 橙色 | TF 未格式化等可恢复警告 |
| 红色 | 启动、UI 恢复或 TF 硬错误 |
| 熄灭 | 深睡或关机 |

红色通道由 M5PM1 提供开关控制，绿色和蓝色通道由 M5IOE1 PWM 控制，因此正常
就绪/连接状态使用低亮 PWM 色，红、黄、紫、橙仅用于异常或短时状态。

未配置 Wi-Fi 时运行的配网 SoftAP 也遵守同一空闲休眠时间，不会让设备永久保持
唤醒；触摸唤醒后 SoftAP 会重新启动。流式内容上传或配网请求仍在进行时会推迟本次
自动休眠，事务完成或中止后恢复正常计时，避免在替换文件中途断电。

保存的 Wi-Fi 无法连接或连接断开时，内容中心自动恢复配网 SoftAP；AP 启动失败
采用 0.5 秒到 30 秒的退避重试，避免紧密重试影响 UI 和射频共存。AP 报告启用
后，后台还会核对独立 SoftAP 接口的模式、SSID 和固定信道 6；连续三次不匹配
会关闭并重新启动 AP，而不是只相信异步启用回调。

设备尚无 STA 凭据时最终运行于 AP-only；ESP32-S3 首次 AP_START 后执行一次
受控 APSTA 到 AP-only 切换，以规避“接口已启动但外部无 beacon”的控制器状态。
每次成功 AP_START 都重建 DHCP，因此该切换不会留下失效地址池；提交凭据后
Zephyr 连接路径再切换为 APSTA。配网射频固定使用
信道 6、20 MHz、802.11b/g/n 兼容模式，关闭 modem power-save，并显式设置合法
的最大发射功率；地区约束由 ESP-IDF 默认 regulatory domain 和硬件校准负责，
固件不强制写死国家码。启动日志会输出回读后的模式、带宽、协议位图和功率，
便于区分配置错误与天线/beacon 问题。sockets service 和 HTTP server 分配独立
eventfd，避免 HTTP listener 因控制 fd 耗尽而持续重启。Wi-Fi 接口通过自检后才启动 BLE，避免两个
共享 2.4 GHz 射频的控制器在热点启动途中互相改变状态。

本地网页用屏幕上的八位 Base32 配对码换取一次性 ticket，再通过 POST 建立只
保存在当前浏览器 origin 的会话；刷新页面会先验证并恢复会话。提交 Wi-Fi 后，
网页在 SoftAP 保留的 20 秒接力窗口内轮询公开状态，取得 STA 的 DHCP 地址后
申请新的 60 秒一次性 ticket，并通过 URL fragment 带到局域网 origin。目标页
立即清除 fragment，再以 POST header 兑换 ticket；长期会话 token 不进入 URL。
上传显示实时进度，认证过期时清除本地会话并回到配对页。

## 持久化设置

内部 NVS 使用 Zephyr Settings 保存。时区、UTC 偏移、24 小时制、休眠时间、
前光亮度、阅读密度、当前应用、阅读页恢复意图以及 Wi-Fi SSID/密码统一存入
`papermono/config`：它是固定大小、带版本和内嵌 CRC32 的单条原子记录。setter
先写完整候选记录，保存成功后才更新 RAM；相同值不会重复写入。SSID 与密码因此
不会在掉电或写失败后形成一新一旧的组合。旧版 `papermono/timezone`、
`sleep_min`、`frontlight`、`wifi_ssid` 等分键数据只用于首次兼容迁移，成功生成原子记录后再
尽力清理，不影响已经提交的新设置。

前光在设置页和阅读菜单均提供 0/25/50/75/100% 五档：轻触或右滑增加，
左滑减少，长按关闭。
调整时先确认 PWM 能应用候选值，再原子保存；NVS 保存失败会立即恢复原亮度，
避免界面、RAM、持久化值和实体灯光出现不一致。

阅读进度与书签按书籍 ID 单独存 `reader/<id>`（版本号 `READER_STATE_VERSION`）。
书签自 v4 起附带该页开头的一段文本摘要，因此书签名不再只是"书签 1"加一个
字节偏移。**记录长度发生变化，v4 之前的阅读状态会被丢弃一次**（长度不匹配的
记录在加载时直接忽略，不会误读），之后恢复正常。

时区与 UTC 偏移会持久化并参与时间换算，但**当前版本没有开放修改入口**：设备
面向单一时区市场，默认 `Asia/Shanghai`（UTC+8），设置页没有剩余空间承载时区
选择列表。若将来需要，应先把设置页改为可滚动列表再挂入
`papermono_settings_set_timezone()`（该函数已实现并通过单元测试）。

阅读会话、最近阅读、书签、个人数据 overlay、BLE bond 和信息卡片缓存仍各自
使用独立命名空间；整本书和用户内容只保存在 TF 卡。

默认值是简体中文界面、`Asia/Shanghai`、UTC+8、24 小时制、10 分钟休眠和
标准阅读密度。局域网连接成功后，后台 SNTP 线程校准系统时间，并把本地时间
写入 RX8130；同步失败只重试，不阻塞 UI。

## 内容限制

- TXT 自动按 BOM、严格 UTF-8 有效性、GBK 顺序识别，也允许手动覆盖。
- EPUB 只支持无 DRM 的文字型 EPUB 2/3；解析 container、OPF、spine、
  NCX/EPUB3 nav 和 XHTML，目录保留父子层级并映射到 spine 章节；忽略 CSS、
  图片、脚本、音视频和复杂表格。
- 单本 TXT/EPUB 最大 64 MiB；元数据文件最大 256 KiB。
- ZIP 解析限制条目数、中央目录、总解压大小、文件名和路径深度，拒绝绝对路径、
  `..` 路径穿越、加密条目和异常压缩包。
- 固件内置 1-bit 字体：24 px Source Han Serif SC 覆盖基础 CJK、ASCII、
  常用标点、全角字符及温度符号；48 px 页头与 40 px 状态标题是固定中文子集。
  16 px Source Han Sans SC 用于元数据与缺字回退，GNU Unifont 补齐其
  `U+9FF0-U+9FFF`。不提供任意字号；来源与生成范围见 `docs/font-licenses.md`。

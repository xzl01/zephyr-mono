# 遥控器配对码出现后控制器断言

2026-10-21，在默认固件 `81e723e` 的遥控器页面连接电脑后，串口捕获到：

```text
BLE assert ke_event.c 200, param 00000000 00000000
```

这是蓝牙控制器的断言；本次串口记录未出现 LVGL 分配失败或 Zephyr 栈哨兵异常。
原始日志和内存快照保存在本地忽略的 `artifacts/remote-crash-*`，不纳入版本库。

## 定位

- 原固件配置启用了 `BT_SMP` 和 `PAPERMONO_BLE_HID`，但
  `ESP32_BT_CTLR_LE_SECURITY_ENABLE` 未启用；控制器启动特性为 `SMP:0`。
- Zephyr 的 ESP HCI 驱动中，该安全开关默认依赖 `BT_CTLR_LE_ENC`。
  后者属于 Zephyr 原生控制器，使用 ESP 厂商 HCI 控制器时不会随主机 SMP 自动开启。
- HAL 的 `esp_bt.h` 将此开关映射到控制器的 `BLE_SECURITY_ENABLE`。
- 断言现场 `ke_event_env` 的待处理位图为 `0x0c`，其中事件 2 的回调为零。
  厂商调度函数对待处理事件缺少回调的情况触发断言。遥控状态仍为已连接、
  未加密、配对码可见，与用户描述的发生时机一致。
- 控制器与 BT RX 栈哨兵完整。现场剩余未使用栈分别为 3180、108 字节；
  未将栈大小或界面堆调整作为此次控制器断言的修复。

## 修改

`PAPERMONO_BLE_HID` 在 ESP32-S3/C3 HCI 平台显式选择控制器安全支持，
避免主机提供配对能力、控制器却没有对应支持的组合。HID 源文件同时添加
编译期断言，禁止缺少控制器安全支持的构建。增加连接、配对码显示、
安全级别、配对成功/失败和断开阶段日志，不输出配对码或对端地址。

原生 LVGL 预览补充正在配对、显示配对码、已加密媒体/演示/鼠标共五种状态。
连同原有未连接状态，六种遥控页面均在 64 KiB 堆内完成渲染；这些是模拟状态，
不能代替实机蓝牙验收。

## 验证

- 主机回归套件通过；六种遥控页面的原生 LVGL 渲染和分配器完整性检查通过。
- 编译期断言的反向编译检查通过：模拟禁用控制器安全支持后编译按预期失败。
- 默认固件构建通过，生成配置中控制器安全支持为 `y`；内部 DRAM 为
  337816 / 399108 字节（84.64%，项目限制 85%）。
- 默认、局刷演示、驱动自检三种构建及各自的内部 DRAM 预算检查通过。
- USB-JTAG 写入和设备端校验通过；独立 ROM 完整回读 SHA-256 与候选固件一致：
  `7b552b6d3739d21b92825c1a3f879d644277f65fa155b7acc6a1bf52c87d1dcd`。
  启动前 NVS 回读与备份逐字节一致，未格式化 TF。
- 新启动日志包含 UI、TF、BLE 就绪，控制器特性变为 `SMP:1`。
  JTAG 复查事件 2 回调已变为 `0x40004d64`，原缺失回调已注册。
- USB 启动证据检查器将 `BLE assert` 纳入失败标记；回归确认即使已打印就绪
  或耐久测试 PASS，只要同次启动出现该断言，也不能判为验证通过。
- 真实电脑输入配对码、按键和重连结果待确认；初始化和事件表复查不等于完成配对。

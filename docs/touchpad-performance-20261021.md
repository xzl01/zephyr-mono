# 遥控触摸板连续位移

用户反馈 Mac 配对成功后触摸板卡顿。旧实现将整个接触过程交给通用手势分类器，
松手后只发送一次固定 40 像素、单轴的移动；不具备跟随手指的连续位移。
右侧滚轮也只在松手后发送一格。

构建使用现有 Zephyr `1f6485eca` 工作树，其中 DMA、Wi-Fi、SoC CMake 和 loader
原有的本地修改均保留；HAL `19f979c` 工作树保持干净。本次未修改这些 SDK 文件。

FT6336 配置轮询间隔为 8 毫秒。原固件实机 HTTP 状态两次读取相隔 2042 毫秒，
触摸帧增加 228，约 111.7 次/秒，读取错误和无效帧均为零。
这是主机驱动的轮询帧率，不能据此证明控制器每次都更新了新的坐标。

修改后的触摸板直接读取按住期间完整的 X/Y 样本，按真实增量持续提交双轴位移。
点击保留 6 像素的抖动容忍；开始移动后，松手不会再触发点击或额外的固定步进。
右侧区域按接触起点锁定为滚轮，保留不足一格的余量；离开区域不会切换手势含义。
最左侧边缘仍保留全局返回手势。

发送经过异步工作项，每 16 毫秒合并一次最新增量，触摸线程不等待蓝牙发送或
墨水屏刷新。短暂缓冲区不足会重试；积压限制为四个最大位移报告，超过 100 毫秒
的旧位移直接丢弃。切换页面或模式时清空待发位移，并使用接触代次阻止旧手势变成
新页面操作。发送期间固定连接引用，积压不会传给重新连接的主机。
原始移动时间通过原子变量交给 UI 线程，在等待输入超时后重新计算空闲时间，
防止连续滑动绕过普通页面事件后触发提前休眠。

蓝牙首选连接间隔由 30–50 毫秒改为 15 毫秒，最终值由 Mac 决定，
通过连接参数回调记录实际间隔。页面刷新和用户感受到的指针延迟分别验证，
不能把 16 毫秒工作项间隔当成端到端延迟。

验证覆盖连续双轴位移、点击抖动、滚轮余量、模式边界、发送合并、拥塞重试、
过期丢弃、页面停用和重新连接隔离。主机回归、六种遥控页面的原生 LVGL 预览通过。
默认固件内部 DRAM 为 338792 / 399108 字节（84.89%，限制 85%）。
Mac 实测接受 15 毫秒连接间隔，随后延迟参数降为 0；恢复保存的配对后安全等级为 4。
连续触摸板候选镜像 SHA-256：
`0d91ac6d392a19ce54d6df6164025ecc9b57254ad4abf952531390508886d679`。
该候选随后在实机验证中被拒绝：重连后约 33 秒，`wifi_task_handle` 发生
`EXCCAUSE 28`，PC 为 `ap_try_sa_query_process`，参数 A2 为零，读取地址为 `0x300`。
此时尚无连续鼠标报告发出。最终 ELF 反汇编表明，厂商 Wi-Fi 定时器将空节点传给
该函数，ROM 存在性检查返回真，随后直接读取 `node + 0x300`。

`papermono_esp_wifi_compat.c` 通过链接包装丢弃空节点调用，非空节点仍交给原函数。
仅 ESP32-S3 Wi-Fi 构建启用，适用于当前 HAL `19f979c` 的回调路径；未修改 HAL。
这是一条已观察到的无效参数保护，空节点在厂商库内产生的完整原因尚未追溯。
主机回归验证空节点不调用原函数、非空节点原样转发；最终 ELF 验证厂商定时器入口
确实调用保护函数。默认、局刷演示、驱动自检固件均构建通过，内部 DRAM 预算通过。

加入 Wi-Fi 保护后已刷入的镜像 SHA-256：
`1579fc5f347fc2a82794ad06500c3b19a5fb70a70a63a178eef9893c602d8eed`。
USB-JTAG 校验和独立 ROM 完整回读均通过，启动前 NVS 与备份逐字节一致，TF 未格式化。
启动后的 95.2 秒观察窗口内，HTTP 成功响应 17 次、触摸轮询约 112.0 Hz，未新增触摸
错误、无效帧或致命异常。该窗口未收到新的空节点回调；保护分支由单测和最终链接验证覆盖。

用户实测确认“流畅多了”。设备累计成功提交 217 份连续鼠标报告，缓冲区重试为零，
HID 最后错误为零；BT RX 栈哨兵完整，最小未使用空间为 476 字节。
这是本次实机操作的结果，发送调度间隔仍不等同于端到端延迟。
